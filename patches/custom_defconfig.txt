# ============================================================================
# Source: https://github.com/ravindu644/Droidspaces-OSS
#         Documentation/Kernel-Configuration.md  (section "Configuring GKI
#         kernels", Step 2)
# Copyright (C) 2026 ravindu644 <droidcasts@protonmail.com>
#
# HOW THIS IS APPLIED
#   The step "Apply Fork Custom Patches" appends this file to
#   kernel_platform/common/arch/arm64/configs/gki_defconfig, immediately
#   before `make gki_defconfig` runs. Because Kconfig honours the LAST
#   assignment, these values win over anything an earlier CI step wrote.
#
# WHY THIS FILE EXISTS AT ALL
#   Upstream already writes most of these, but the exact set has changed over
#   time. The kernel currently running on this device was built 2026-06-30,
#   BEFORE `CONFIG_USER_NS=y` was added, so it shipped with user namespaces
#   absent and `docker-compose up` failed. Declaring the full block here means
#   the set is explicit, reviewable, and immune to upstream drift.
#
# KABI SAFETY
#   These options are kABI-safe ONLY in combination with the SYSVIPC kABI fix
#   patch that the CI's "Add Droidspaces support" step applies. Do not enable
#   anything beyond this block on a GKI kernel without checking the doc.
#
# ============================================================================

# --- IPC -------------------------------------------------------------------
CONFIG_SYSVIPC=y
CONFIG_POSIX_MQUEUE=y

# --- Namespaces ------------------------------------------------------------
CONFIG_IPC_NS=y
CONFIG_PID_NS=y

# --- HW access -------------------------------------------------------------
CONFIG_DEVTMPFS=y

# --- Networking (enhanced NAT support) -------------------------------------
CONFIG_NETFILTER_XT_MATCH_ADDRTYPE=y

# --- Fix for the "docker unsafe procfs" error ------------------------------
# This is the one that was missing on the 2026-06-30 build.
CONFIG_USER_NS=y

# --- UFW support -----------------------------------------------------------
# NOTE: the Droidspaces doc lists CONFIG_NETFILTER_XT_TARGET_REJECT=y, but that
# symbol does not exist in this kernel -- zero occurrences across every
# netfilter Kconfig (net/netfilter, net/ipv4/netfilter, net/ipv6/netfilter,
# net/bridge/netfilter). Kconfig silently ignores unknown symbols, so the CI
# has been appending it as a no-op all along.
#
# The real iptables REJECT target is CONFIG_IP_NF_TARGET_REJECT, which depends
# on CONFIG_IP_NF_FILTER. Both were already =y in the known-good Pad 3 kernel,
# confirmed from the device's own /proc/config.gz.
CONFIG_IP_NF_FILTER=y
CONFIG_IP_NF_TARGET_REJECT=y
CONFIG_NETFILTER_XT_TARGET_LOG=y
CONFIG_NETFILTER_XT_MATCH_RECENT=y

# --- Fail2ban support ------------------------------------------------------
CONFIG_IP_SET=y
CONFIG_IP_SET_HASH_IP=y
CONFIG_IP_SET_HASH_NET=y
CONFIG_NETFILTER_XT_SET=y

# --- xattr / POSIX ACL on tmpfs (NixOS support) ----------------------------
CONFIG_TMPFS_POSIX_ACL=y
CONFIG_TMPFS_XATTR=y

# ============================================================================
# RESOLVED QUESTION - cgroup `devices` / `pids` controllers
# ============================================================================
# The Droidspaces doc's "what to do if something is missing" table calls these
# FATAL for containers:
#
#     Cgroup device | CONFIG_CGROUP_DEVICE=y | Fatal. Containers cannot start.
#
# Measured on this device, /proc/cgroups lists only:
#     cpuset cpu cpuacct blkio memory freezer net_prio
# i.e. the `devices` and `pids` controllers are genuinely absent.
#
# ANSWERED by running the tool itself on the device:
#
#     su -c /data/local/Droidspaces/bin/droidspaces check
#     Droidspaces v6.6.0 ...
#       [✓] Cgroup v2 support
#       [✓] Cgroup namespace
#       [✗] Sandboxing (user namespaces)
#             CONFIG_USER_NS; enable per container with --allow-sandboxing.
#             Needed by unprivileged Docker and Podman, ...
#     Summary:
#       [✓] All required features found!
#
# Droidspaces v6.6.0 does NOT check for the devices/pids controllers and
# reports every required feature present without them. The doc's table applies
# to its non-GKI advice; for GKI the omission is deliberate and correct.
#
# => CONFIG_CGROUP_DEVICE / CONFIG_CGROUP_PIDS are NOT needed.
#    The only missing feature was CONFIG_USER_NS, which is enabled above.
#
# If a future Droidspaces release starts flagging cgroup controllers, add them
# here - but do not enable them speculatively.
